# Hermes Gunpla News Mechanism — Full Reproduction Guide

## Purpose
This document explains exactly how the Hermes Gunpla news pipeline works, what broke, and how to replicate it on another machine or in another agent context.

---

## 1. High-Level Architecture (3 Levels)

### Level 1 — Trigger / Router
- Input: `What’s the latest Gunpla news? [optional topic]`
- Router logic:
  - If topic matches `life-size`, `odaiba`, `unicorn gundam statue` → **focused brief mode**
  - Else → **full brief mode** (latest N articles)
- Skills loaded in order:
  1. `gunpla-news-gatherer`
  2. `gunpla-source-guide`
  3. `gunpla-verification`

### Level 2 — Source Gathering (direct HTTP only)
**Hard constraint:** Do NOT use `web_search`, Firecrawl, or any managed search tool. Environment has no credits.

Primary fetcher: `urllib.request` / `curl` with browser User-Agent header.

Sources in priority order:
1. `https://en.gundam-official.com/news/` — homepage listing
2. `https://en.gundam-official.com/news/<id>` — individual article pages
3. `https://global.bandai-hobby.net/en-us/site/gbase_worldtour/` — event pages

Output: raw candidate list of dicts with `id`, `title`, `date`, `series`, `categories`, `thumb`, `imgs`.

### Level 3 — Verification + Working Data + Export
Apply verification rules, build Working Data table, export to MD + JSON.

## 4. Confidence Labels (from gunpla-verification)

| Label | Meaning |
|---|---|
| `High` | Official or primary retail confirms it; I checked the page myself |
| `Medium` | Primary retail confirms availability but not first reveal; credible community corroboration |
| `Low` | Competitor/community source without independent official confirmation |
| `RUMOR` | Single-source Reddit, YouTube-only, or unconfirmed leak |

### Mandatory checks before marking High
- [ ] Did I open the official or primary retail page myself?
- [ ] If the only source is a competitor, did I find the same fact on official/primary retail?
- [ ] If either is no → downgrade to Medium/Low/RUMOR

### Never output in Verified Brief
- Dates from YouTube video chapters alone
- "Expected Q4 2026" without at least one official Bandai/Gundam-Official mention
- Prices from eBay/Amazon resale — only official MSRP
- Reddit single-source claims as fact
- Competitor-only claims as fact
- RUMOR items unless user explicitly requests them

## 7. Image Verification Pattern

```python
import urllib.request

def verify_image(url):
    req = urllib.request.Request(url, method='HEAD')
    with urllib.request.urlopen(req, timeout=10) as r:
        return r.status == 200 and r.headers.get('Content-Type','').startswith('image')

# Usage:
# for url in extracted_urls:
#     safe = verify_image(url)
#     mark image_checked=true only if safe
```

### Image reuse rule
Official site footer states: `*Note: Reproduction of content and images is strictly prohibited.`

→ Flag all article images as `reuse_not_permitted` unless explicit permission is obtained.
→ Never use site chrome/footer images (`resized_Rectangle_*`).

## 8. Reddit / Community Consensus Rules

- 1 Reddit post alone is NOT enough
- Require ≥3 separate posts/comments corroborating same fact, OR comment must directly cite official Bandai/Gundam-Official source
- High-credibility Reddit poster/mod role does NOT replace 3-source rule unless linking primary material
- If Reddit is inaccessible from the environment → log as `community_consensus: "unavailable — Reddit blocked"` and continue without it

- ❌ Outputting RUMOR items in Verified Brief unless explicitly requested

## 11. What Broke Now and Why

### Symptom
Recent attempts to parse `en.gundam-official.com/news/` homepage and individual article pages return:
- `N/A` for title, date, series, categories when using simple regex
- Reddit JSON/search endpoints return `HTTP 403: Blocked`

### Root Cause 1 — Next.js escaped JSON chunks
The site is a Next.js app. Article metadata is embedded inside `self.__next_f.push([1,"..."])` script tags with multiple layers of escaping:
- Inner JSON uses `\"` for quotes
- Outer JS string uses `\\"` for escaped quotes
- Unicode escapes like `\u0022` for `"`

Simple regex like `'"headline":"([^"]+)"'` fails because the actual text in the HTML contains backslash-escaped quotes, not plain quotes.

**What worked:** Earlier in this session, the same article page DID return metadata when parsed from the `newsResponse` JSON blob embedded in the page. That parsing succeeded because the article content was present in a less-escaped form in the initial page load.

**What broke:** Subsequent fetches of the same article returned the same HTML, but regex patterns didn't match because the escaping context changed between fetches, or because the regex was too strict for the actual escaped content.

### Root Cause 2 — Reddit 403
Reddit’s JSON endpoints (`/r/gunpla/search.json`, `/r/gunpla/hot.json`, old.reddit.com) are blocking requests from this environment’s IP or User-Agent. This is likely due to:
- Missing/modified `User-Agent` not matching Reddit’s API rules
- IP-based rate limiting
- Environment network policy

**Workaround:** Use `pushshift.io` or other Reddit archivers, but those also returned 403. The only reliable path is to paste specific Reddit thread URLs directly.

### Root Cause 3 — Homepage ID extraction changed
The homepage regex `re.findall(r'/news/([a-z0-9]+)', html)` now picks up non-article paths like `page-7994191b4d2d9991.js` and `detail/?id=...`. These are not valid article IDs.

**Why:** The homepage structure changed, or the regex is too broad and matches script chunk URLs and routing placeholders.

### Step 2: Fetch latest article IDs
```python
import urllib.request, re

headers = {'User-Agent':'Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36'}
html = urllib.request.urlopen(urllib.request.Request('https://en.gundam-official.com/news/', headers=headers), timeout=15).read().decode('utf-8', errors='ignore')

# Filter only valid article IDs (longer than 5 chars, not 'page'/'detail')
raw_ids = re.findall(r'/news/([a-z0-9]+)', html)
ids = []
for i in raw_ids:
    if i not in ids and len(i) > 5 and i not in ['page', 'detail']:
        ids.append(i)
```

### Step 3: Extract article metadata
**Critical:** The homepage listing has clean metadata. Individual article pages have escaped metadata. Try homepage first.

```python
# Option A: Homepage listing (cleaner)
articles = re.findall(r'<article[^>]*>.*?</article>', html, re.DOTALL)
# or parse the JSON newsResponse block

# Option B: Individual article (escaped)
ahtml = urllib.request.urlopen(urllib.request.Request(f'https://en.gundam-official.com/news/{id}', headers=headers), timeout=10).read().decode('utf-8', errors='ignore')

# Find the newsResponse JSON blob
m = re.search(r'"newsResponse":\{(.*?)\}', ahtml, re.DOTALL)
if m:
    blob = m.group(1)
    # Unescape layers
    blob = blob.replace('\\\\"', '"').replace('\\u0022', '"')
    # Now extract
    title = re.search(r'"title":"([^"]+)"', blob)
```
